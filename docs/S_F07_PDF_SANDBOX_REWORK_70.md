# F07 PDF sandbox rework for issue #70

This branch is an engineering candidate for an ephemeral Docker parser of PDF bytes that have already passed `FULL_REQUIRED` admission. It does not grant rights or scientific acceptance. The public `check_pdf_page_excerpt_sandboxed` entrypoint accepts only a reviewed `repository@sha256:<64 hex>` image reference and checks that exact reference in local `RepoDigests`. The private `_check_synthetic_pdf_fixture` entrypoint accepts a tag only for the reserved invented fixture carrier and matching `SESHAT_SYNTHETIC_PDF_TEST_IMAGE`; this Python helper is **not** a security boundary against adversarial in-process callers.

The host validates the child's response schema, digest shape, extractor version, page count and offset bounds. The extractor's page text, page count, text hash and offset remain `CHILD_ASSERTED_UNATTESTED`: the parent cannot independently prove those observations without parsing the PDF outside the container. The receipt is owner-private; it and its short-excerpt fingerprints must not be passed through a customer export. `NOT_VERIFIED` is the typed result for an absent or ambiguous quote; process and OS failures remain separate.

The sandbox profile accepts at most 8 MiB even though F07 can admit 50 MiB. At most two live calls per process are admitted. Excess size returns `SANDBOX_INPUT_LIMIT` before Docker launch; a busy or uncertain-cleanup process fails closed. If forced cleanup cannot be confirmed, the original failure is retained, a source-free container-name diagnostic is emitted on private stderr, and later calls in that process are denied.

The GitHub workflow has networked dependency/image preparation followed by no-network, read-only Docker tests. Its bounded drills check no default container route, read-only filesystem refusal and a hard deadline followed by named-container cleanup. A final residual-container check runs even if pytest fails. These drills need exact-new-SHA Actions evidence; they are not target-host OOM, PID-limit or CPU-cap proofs.

Before real untrusted PDF use: owner F07 legal rights and selection; review of target daemon isolation and exact image digest/base and extractor bytes; observed OOM and forced-cleanup behavior on the target runtime; fresh independent source review; separate human scientific and customer acceptance. AORUS Docker CLI alone does not provide a working Linux daemon. No privileged issuer server is part of this design.
